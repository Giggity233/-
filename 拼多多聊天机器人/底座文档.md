说明：本文只写**底座**（本地主程序）。发送消息、转人工、商品采集都在 Coze 插件里，插件文档见 `coze插件` 目录。

## 一、底座做什么

**监听店铺聊天页的 WebSocket → 合并整理消息 → 上传 Coze 工作流 → 只记录日志。**

底座不做任何发送动作（发消息 / 发图片 / 发视频 / 转人工 / 商品采集上传），这些全部由 Coze 工作流调用插件完成。

## 四、运行流程

### 1. 启动
1. 输入监控分组号（如 `1`）；
2. 读 `D:\aibot\user_login_info.json` 取该分组的店铺列表（`username` / `password` / `port`）；
3. 读 `data\coze.json`，选择客户 → 拿 `workflow_id`；
4. 每个店铺一个守护线程（启动错开 2~3 秒）。

### 2. 单店铺启动（`monitor_shop` → `chatmain`）
1. 用 CDP 端口接管浏览器页面，打开 `https://mms.pinduoduo.com/chat-merchant/#/`，1 秒后刷新一次；
2. `pddgetshopname` 取店铺名（后面日志都用它）；
3. `pddchange_state(cookies, 1)` **强制在线**（不在线收不到 WS 推送）；
4. **转接人预检** → 日志 `店铺{店铺名}转接人{csid}`：
   - 中控平台查该店铺专员账号（`zk_api.huoqu_zhuanyuan`）
   - 拼多多后台查可转接客服列表（`pddtransfer_query`）
   - 两边按 账号名 / 账号ID 匹配出 `csid`
   - 查不到 → 记运行日志 + 中控平台建一条**紧急待办**（警示提醒）
   - **平台连不上 → 直接抛异常**，由 `monitor_shop` 记「店铺运行异常」并等 300 秒重启（不掩盖故障）
5. 启动 WS 监听。

### 3. 消息处理（每条 WS 帧）
1. `pdd_ws.run` 解码帧 → 只处理 `push_type=2` 的推送；
2. 按买家 uid 缓冲合并：**首条 6 秒、后续 4 秒**，每批最多处理 120 秒；
3. `print_and_return_messages` 整理：
   - 只取 WS 自带字段：`userid` / `shopid` / `username` / `content` / `msgid` / `template_name`
   - `clean_media_text`：只保留图片链接，视频和其它链接删掉；空内容 → `user_goods_card`
   - 命中 `xithf` 系统关键词 → `zdyi`（不处理）；命中 `zhuan` 模板 → `转人工`；命中 `buzhuan` 模板 → 原样回传
   - 内容含「将该会话转移给」→ 整条丢弃
4. 注入 `cook`（浏览器实时 cookie 字符串）和 `anti`（执行 anti.js 实时生成）；
5. 调 Coze `/v1/workflow/run`，拿返回值**只写日志**：
   - `聊天记录` 日志：`店铺{店铺名}{uid}:{消息内容}`
   - `聊天记录` 日志：`Coze返回 {uid}:{Coze返回值}`
6. 返回值格式约定 `xxxx@@@@真实回复`，由 Coze 工作流负责调插件发送。

### 4. 异常处理
- 单条消息解析失败 → 跳过，不影响监听；
- 店铺线程任何异常 → `monitor_shop` 捕获，写 `异常监控日志`，等 300 秒重新初始化页面再跑；
- WS 断线 → 30 秒心跳×3 无消息 / 收到 Closed → 刷新页面重建 CDP 驱动重连。

### 5. 关键词热加载
`data\xitong.json` 每 `config_refresh_interval`（默认 3600 秒）自动重载，改关键词不用重启。

## 五、底座用到的接口（共 6 个）

### 启动时（每个店铺一次）

| 接口 | 代码位置 | 用途 |
|---|---|---|
| `POST https://mms.pinduoduo.com/plateau/chat/set_csstatus` | `pdd_api.pddchange_state` | 强制客服在线 |
| `GET https://mms.pinduoduo.com/earth/api/mallInfo/commonMallInfo` | `pdd_api.pddgetshopname` | 取店铺名（日志用） |
| `GET {中控平台}/api/v1/cookies/?platform=pdd` | `zk_api.huoqu_zhuanyuan` | 取该店铺专员账号（转接人预检） |
| `POST https://mms.pinduoduo.com/latitude/assign/getAssignCsList` | `pdd_api.pddtransfer_query` | 可转接客服列表（预检匹配 csid） |

### 仅转接人为空时

| 接口 | 代码位置 | 用途 |
|---|---|---|
| `POST {中控平台}/api/v1/pending-tasks/create/` | `zk_api.add_pending_task` | 警示提醒（建紧急待办） |

### 每条消息

| 接口 | 代码位置 | 用途 |
|---|---|---|
| `POST https://api.coze.cn/v1/workflow/run` | `coze_api.cozeduihua` | 调工作流，取返回值写日志 |

### 不是业务接口的两处

- **CDP**：连本机浏览器 `ws://127.0.0.1:<端口>/devtools/page/<tab_id>`，`Network.enable` + 收 WS 帧（消息来源）；
- **浏览器导航**：`page.get('https://mms.pinduoduo.com/chat-merchant/#/')`。

中控平台地址常量：`zk_api.BASE_URL = "http://117.72.204.36:8000"`（换地址只改这里 + 各 Coze 插件里的同名常量）。

## 六、日志

路径：`log\<店铺名或账号>\<文件名>.log`，50MB 分割、保留 7 天。

| 日志文件 | 内容 |
|---|---|
| `聊天记录.log` | `店铺X买家uid:消息内容`、`Coze返回 uid:返回值` |
| `运行日志.log` | 启动信息、`已强制在线`、`店铺X转接人Y`、接口/异常信息 |
| `异常监控日志.log` | `店铺运行异常: ...`、掉线、重连 |

控制台标题会显示 `分组<N>`，方便多开区分。

## 七、Coze 返回值约定（工作流侧）

| 返回形态 | 含义 |
|---|---|
| `xxx@@@@正常文字` | 由工作流调「推发消息」插件发文字 |
| 含 `人工` | 工作流调「转人工」插件（插件内部会先发「稍等亲亲，这边让对接客服来回复您」再转接） |
| `[视频]::::地址` | 调「推发消息」插件发视频 |
| `[图片]::::地址@@高@@宽@@大小` | 调「推发消息」插件发图片 |

底座只负责把返回值记进日志，不做任何动作。
