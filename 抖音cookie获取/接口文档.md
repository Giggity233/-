# 联樽中控平台接口文档

## 基础约定

- 服务地址示例：`http://127.0.0.1:8000`
- 所有采集接口均使用 JSON 请求体（GET 请求除外），不需要 `HEADERS`、Cookie 或 API Key。
- 平台可传英文 `pdd` / `douyin`，也可传中文 `拼多多` / `抖音`。
- 成功响应统一有 `{"ok": true}`；失败响应为 `{"ok": false, "message": "原因"}`。

下面示例共用：

```python
import requests

BASE_URL = "http://127.0.0.1:8000"
```

## 1. 获取所有启用客户

`GET /api/v1/customers/`

返回 `id` 和客户 `name`；禁用客户不返回。

```python
response = requests.get(f"{BASE_URL}/api/v1/customers/", timeout=15)
response.raise_for_status()
customers = response.json()["data"]
print(customers)
```

## 2. 新增或更新店铺 Cookie

`POST /api/v1/cookies/upsert/`

接口会先以 `shop_id` 查找已有店铺。已有且店铺编号唯一时，只传 `shop_id` 与 `cookie` 即可更新 Cookie 和更新时间；若该编号跨平台重复，请额外传 `platform` 进行区分。找不到已有店铺时，会新建店铺并进入无主店铺中心，此时必须提供店铺基本信息。客户**不能也不需要**通过此接口上传，后续由用户在无主店铺认领时手工绑定。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 新增时是；更新跨平台重复编号时是 | `pdd`、`douyin` 或中文平台名 |
| `shop_id` | 是 | 店铺 ID/编号 |
| `shop_name` | 新增时是 | 店铺名称 |
| `cookie` | 是 | 完整 Cookie 字符串 |
| `main_category` | 否 | 主营类目，缺省为 `notfind` |
| `cookie_status` | 否 | `valid`、`invalid` 或 `disabled`，默认 `valid` |

```python
payload = {
    "platform": "pdd",
    "shop_id": "pdd_90001",
    "shop_name": "联樽旗舰店",
    "cookie": "PDDAccessToken=example; ...",
    "main_category": "家居百货",
}
response = requests.post(f"{BASE_URL}/api/v1/cookies/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json())
```

仅更新已有店铺 Cookie：

```python
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/upsert/",
    json={"shop_id": "pdd_90001", "cookie": "新的完整Cookie"},
    timeout=15,
)
response.raise_for_status()
```

## 3. 按平台获取 Cookie 信息

`GET /api/v1/cookies/?platform={platform}`

返回该平台全部店铺的店铺 ID、店铺名、所属客户、主营类目、Cookie 状态和更新时间，以及该店铺的原始 `cookie`。每个店铺还会返回人工账号、机器人账号的账号名及 ID。人工账号额外返回 `account_type`、`account_type_name`、`login_account` 和 `login_password`。没有抓取到 ID 时，字段为 `该id没抓`。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "拼多多"},
    timeout=15,
)
response.raise_for_status()
for shop in response.json()["data"]:
    print(shop["shop_name"], shop["shop_id"], shop["human_accounts"], shop["bot_accounts"])
```

## 4. 按平台和客户获取 Cookie 信息

仍使用 `GET /api/v1/cookies/`，在平台基础上额外提供客户名称或客户 ID。

```python
# 按客户名称
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer": "华东客户"},
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])

# 按客户 ID
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer_id": 1},
    timeout=15,
)
```

## 5. 将店铺 Cookie 标记为失效

`POST /api/v1/cookies/invalidate/`

`shop_id` 为必填。若同一店铺编号在两个平台同时存在，请同时传 `platform`，避免误操作。

```python
payload = {"shop_id": "pdd_90001", "platform": "pdd"}
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/invalidate/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 6. 上传店铺运营数据

`POST /api/v1/store-metrics/upsert/`

数据会覆盖该店铺的同名最新指标，并自动记录数据更新时间。负责人由系统在首次认领店铺时确定，不接收接口上传。店铺数据仅是客观店铺数据，不区分负责人 1、负责人 2，也不参与客服班次统计。

`shop_id` 和 `time` 必填。`time` 是 `0` 到 `23` 的整数，代表这份数据属于当天的哪个整点小时；即使补传历史小时数据，也必须传对应的 `time`。当店铺编号可能跨平台重复时，`platform` 必填。可选的 `report_date` 使用 `YYYY-MM-DD`，用于补传其他日期；不传默认当天。其余指标均可按实际采集情况选择性传递，未传指标保留上一次数值。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `consultation_count` | 整数 | 咨询数 |
| `three_minute_reply_rate` | 数字 | 3 分钟回复率，如 `98.50` |
| `timeout_count` | 整数 | 超时数量 |
| `average_response_seconds` | 数字 | 平均响应速度（秒） |
| `pending_after_sales` | 整数 | 待处理售后数量 |
| `pending_tickets` | 整数 | 待处理工单数量 |
| `today_order_count` | 整数 | 今日订单数 |
| `today_turnover` | 数字 | 今日营业金额 |
| `today_ad_spend` | 数字 | 今日广告金额 |
| `today_refund` | 数字 | 今日退款金额 |
| `robot_completed_reply_count` | 整数 | 机器人完结回复数量 |
| `robot_completed_reply_rate` | 数字 | 机器人完结回复率 |
| `robot_transferred_count` | 整数 | 机器人转出数量 |

所有数值必须大于或等于 0。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time": 16,
    "report_date": "2026-09-15",
    "consultation_count": 186,
    "three_minute_reply_rate": 97.80,
    "timeout_count": 4,
    "average_response_seconds": 82.5,
    "pending_after_sales": 9,
    "pending_tickets": 2,
    "today_order_count": 68,
    "today_turnover": 12580.30,
    "today_ad_spend": 860.00,
    "today_refund": 430.50,
    "robot_completed_reply_count": 31,
    "robot_completed_reply_rate": 16.67,
    "robot_transferred_count": 12,
}
response = requests.post(
    f"{BASE_URL}/api/v1/store-metrics/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 7. 上传客服班次日总结（月度回复来源）

`POST /api/v1/shift-daily-summaries/upsert/`

此接口用于上传早班或晚班各自独立的最终基线。传参字段与店铺数据接口相同；另需提供当班 `shift` 和明确的 `year`、`month`、`day`。系统根据店铺当前该班次的认领人，直接将该值归档为客服绩效和月度回复。店铺数据中心的小时数据不会参与该统计。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "shift": "evening",
    "year": 2026,
    "month": 9,
    "day": 15,
    "consultation_count": 88,
    "timeout_count": 2,
    "robot_completed_reply_count": 19,
    "robot_completed_reply_rate": 21.59,
    "robot_transferred_count": 7,
}
response = requests.post(
    f"{BASE_URL}/api/v1/shift-daily-summaries/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 8. 获取店铺最新早班基线

`GET /api/v1/shift-baselines/morning/?id={店铺ID}`

仅传店铺 ID 即可获取该店铺最近一次上传的早班基线，包含早班客服、日期及全部班次指标。`id` 优先按店铺编号匹配；若传数字且找不到店铺编号，会回退按系统店铺主键查询。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/shift-baselines/morning/",
    params={"id": "pdd_90001"},
    timeout=15,
)
response.raise_for_status()
morning_baseline = response.json()["data"]
print(morning_baseline)
```

## 9. 按系统账号名获取名下店铺

`GET /api/v1/account-stores/?account_name={系统账号名}`

返回该系统账号在无主店铺中心认领的全部店铺，以及其担任的“负责人 1”或“负责人 2”席位。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/account-stores/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
shops = response.json()["data"]
print(shops)
```

## 10. 回传人工/机器人账号 ID

`POST /api/v1/accounts/capture-id/`

账号必须先在“账号管理中心”创建。传账号名和账号 ID 即可；若账号名可能在多个店铺相同，建议额外传 `shop_id` 来精确限定。

```python
payload = {
    "account_name": "拼多多客服01",
    "account_id": "account_812345",
    "shop_id": "pdd_90001",  # 可选，但推荐传
}
response = requests.post(
    f"{BASE_URL}/api/v1/accounts/capture-id/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 11. 创建待处理事务

`POST /api/v1/pending-tasks/create/`

按店铺创建一条待处理事务。`time_type` 只能传 `normal`（普通）或 `urgent`（紧急），也支持传中文“普通”或“紧急”。使用系统店铺主键时传 `store_id`；使用店铺编号时传 `shop_id`。若同一编号跨平台重复，请额外传 `platform`。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time_type": "urgent",
    "handling_item": "客户申请退款，请尽快跟进",
}
response = requests.post(
    f"{BASE_URL}/api/v1/pending-tasks/create/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])
```

返回数据包含店铺名、处理事项、`is_urgent`、创建时间，以及实时计算的 `elapsed_time`（已等待时间）。

## 12. 获取负责人未处理事务

`GET /api/v1/pending-tasks/`

此接口需要已登录的平台会话。普通负责人只能拿到自己认领店铺的未处理事务；管理员或具有“查看全部店铺数据”权限的用户默认拿到全部。管理员可追加 `account_name={系统账号名}`，筛选指定负责人的事务。

```python
# 当前登录负责人自己的待办
response = requests.get(f"{BASE_URL}/api/v1/pending-tasks/", timeout=15)

# 管理员查看某位负责人名下的待办
response = requests.get(
    f"{BASE_URL}/api/v1/pending-tasks/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
tasks = response.json()["data"]
```

工作台的“标记已处理”按钮会将对应事务置为已处理，并记录处理人和处理时间；已处理事务不会再出现在该接口或工作台列表中。

## 常见状态码

| 状态码 | 含义 |
| --- | --- |
| `200` | 查询或更新成功 |
| `201` | 已创建新的店铺 Cookie |
| `400` | 参数缺失、字段格式错误或 JSON 不合法 |
| `404` | 店铺或账号不存在 |
| `409` | 店铺编号跨平台重复，需要补传 `platform` |
