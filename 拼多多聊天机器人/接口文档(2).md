# 蘑菇头中控平台接口文档

## 基础约定

- 服务地址示例：`http://127.0.0.1:8000`
- 所有采集接口均使用 JSON 请求体（GET 请求除外），不需要 `HEADERS`、Cookie 或 API Key。
- 平台可传英文 `pdd` / `douyin`，也可传中文 `拼多多` / `抖音`。
- 成功响应统一有 `{"ok": true}`；失败响应为 `{"ok": false, "message": "原因"}`。

下面示例共用：

```python
import requests

BASE_URL = "[http://127.0.0.1:8000](http://117.72.204.36:8000)"
```

## 1. 获取所有启用客户

`GET /api/v1/customers/`

返回 `id` 和客户 `name`；禁用客户不返回。

```python
response = requests.get(f"{BASE_URL}/api/v1/customers/", timeout=15)
response.raise_for_status()
customers = response.json()["data"]
print(customers)
```

## 2. 新增或更新店铺 Cookie

`POST /api/v1/cookies/upsert/`

接口会先以 `shop_id` 查找已有店铺。已有且店铺编号唯一时，只传 `shop_id` 与 `cookie` 即可更新 Cookie 和更新时间；若该编号跨平台重复，请额外传 `platform` 进行区分。找不到已有店铺时，会新建店铺并进入无主店铺中心，此时必须提供店铺基本信息。客户**不能也不需要**通过此接口上传，后续由用户在无主店铺认领时手工绑定。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 新增时是；更新跨平台重复编号时是 | `pdd`、`douyin` 或中文平台名 |
| `shop_id` | 是 | 店铺 ID/编号 |
| `shop_name` | 新增时是 | 店铺名称 |
| `cookie` | 是 | 完整 Cookie 字符串 |
| `main_category` | 否 | 主营类目，缺省为 `notfind` |
| `cookie_status` | 否 | `valid`、`invalid` 或 `disabled`，默认 `valid` |

```python
payload = {
    "platform": "pdd",
    "shop_id": "pdd_90001",
    "shop_name": "蘑菇头旗舰店",
    "cookie": "PDDAccessToken=example; ...",
    "main_category": "家居百货",
}
response = requests.post(f"{BASE_URL}/api/v1/cookies/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json())
```

仅更新已有店铺 Cookie：

```python
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/upsert/",
    json={"shop_id": "pdd_90001", "cookie": "新的完整Cookie"},
    timeout=15,
)
response.raise_for_status()
```

## 3. 按平台获取 Cookie 信息

`GET /api/v1/cookies/?platform={platform}`

返回该平台全部店铺的店铺 ID、店铺名、所属客户、主营类目、Cookie 状态和更新时间，以及该店铺的原始 `cookie`。每个店铺还会返回专员账号、机器人账号的账号名及 ID。专员账号额外返回 `account_type`、`account_type_name`、`login_account` 和 `login_password`。没有抓取到 ID 时，字段为 `该id没抓`。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "拼多多"},
    timeout=15,
)
response.raise_for_status()
for shop in response.json()["data"]:
    print(shop["shop_name"], shop["shop_id"], shop["human_accounts"], shop["bot_accounts"])
```

## 4. 按平台和客户获取 Cookie 信息

仍使用 `GET /api/v1/cookies/`，在平台基础上额外提供客户名称或客户 ID。

```python
# 按客户名称
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer": "华东客户"},
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])

# 按客户 ID
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer_id": 1},
    timeout=15,
)
```

## 5. 将店铺 Cookie 标记为失效

`POST /api/v1/cookies/invalidate/`

`shop_id` 为必填。若同一店铺编号在两个平台同时存在，请同时传 `platform`，避免误操作。

```python
payload = {"shop_id": "pdd_90001", "platform": "pdd"}
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/invalidate/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 6. 上传专员店铺运营数据

`POST /api/v1/store-metrics/upsert/`

此接口只上传专员及非机器人店铺指标，会覆盖同名最新指标并自动记录更新时间。负责人由系统在首次认领店铺时确定，不接收接口上传。机器人数据必须改用下一节的独立接口。店铺数据仅是客观店铺数据，不区分负责人 1、负责人 2，也不参与专员班次统计。

`shop_id` 和 `time` 必填。`time` 是 `0` 到 `23` 的整数，代表这份数据属于当天的哪个整点小时；即使补传历史小时数据，也必须传对应的 `time`。当店铺编号可能跨平台重复时，`platform` 必填。可选的 `report_date` 使用 `YYYY-MM-DD`，用于补传其他日期；不传默认当天。其余指标均可按实际采集情况选择性传递，未传指标保留上一次数值。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `specialist_reply_count` | 整数 | 专员回复数量 |
| `specialist_three_minute_reply_rate` | 数字 | 专员 3 分钟回复率，如 `98.50` |
| `specialist_timeout_count` | 整数 | 非拼多多店铺的专员超时数量；拼多多会由系统自动计算 |
| `specialist_yesterday_average_response_seconds` | 数字或文字 | 专员昨日平均响应（秒） |
| `pending_after_sales` | 整数 | 待处理售后数量 |
| `pending_tickets` | 整数 | 待处理工单数量 |
| `today_order_count` | 整数 | 今日订单数 |
| `today_turnover` | 数字 | 今日营业金额 |
| `today_ad_spend` | 数字 | 今日广告金额 |
| `store_experience_score` | 数字 | 店铺体验分 |
| `service_experience_score` | 数字或文字 | 服务体验分 |

`咨询数`不再由本接口传入，系统会始终按“专员回复数量 + 机器人完结回复数量”计算。机器人没有数据、传 `null` 或出现文字状态时，机器人完结回复数量按 `0` 参与计算。

数值指标必须大于或等于 0。任一指标也可以传 `null`（Python 调用时为 `None`）或文字，例如 `"无权限"`、`"接口维护中"`；页面会保留相应状态并写入对应历史小时快照。

拼多多的专员超时数量和机器人超时数量均由系统按“总咨询人数 ×（1 − 3 分钟人工回复率）”计算，接口上传的这两个原始值不会采用。

拼多多 `https://mms.pinduoduo.com/chats/getCsRealTimeReplyData` 的响应也可直接作为此接口请求体的一部分：在外层补齐 `shop_id`、`platform` 和 `time` 后，系统会读取 `result.recv_user` 写入专员回复数量，并将 `result.reply_rate` 从小数换算为百分比后写入专员 3 分钟回复率。例如 `reply_rate: 1.0` 会保存为 `100.00%`。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time": 16,
    "report_date": "2026-09-15",
    "specialist_reply_count": 155,
    "specialist_three_minute_reply_rate": 97.80,
    "specialist_yesterday_average_response_seconds": 82.5,
    "pending_after_sales": 9,
    "pending_tickets": 2,
    "today_order_count": 68,
    "today_turnover": 12580.30,
    "today_ad_spend": 860.00,
    "store_experience_score": 4.82,
    "service_experience_score": "无权限",
}
response = requests.post(
    f"{BASE_URL}/api/v1/store-metrics/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 7. 上传机器人店铺数据

`POST /api/v1/robot-metrics/upsert/`

此接口只上传机器人指标。`shop_id`、`time` 必填，`platform`、`report_date` 的规则与专员店铺数据接口相同。每次上传后，系统会用最新的专员回复数量和机器人完结回复数量自动重算咨询数；机器人完结回复数量为 `null`、文字状态或没有上传时，按 `0` 计算。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `robot_completed_reply_count` | 整数或文字 | 机器人完结回复数量 |
| `robot_completed_reply_rate` | 数字或文字 | 机器人完结回复率 |
| `robot_transferred_count` | 整数或文字 | 机器人转出数量 |
| `robot_timeout_count` | 整数或文字 | 非拼多多店铺的机器人超时数量；拼多多会由系统自动计算 |
| `robot_three_minute_reply_rate` | 数字或文字 | 机器人 3 分钟回复率 |

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time": 16,
    "report_date": "2026-09-15",
    "robot_completed_reply_count": 31,
    "robot_completed_reply_rate": 16.67,
    "robot_transferred_count": 12,
    "robot_three_minute_reply_rate": 99.10,
}
response = requests.post(
    f"{BASE_URL}/api/v1/robot-metrics/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 8. 上传专员班次日总结（月度回复来源）

`POST /api/v1/shift-daily-summaries/upsert/`

此接口用于上传早班或晚班各自独立的专员最终基线。传参字段与专员店铺数据接口相同（不接收机器人字段）；另需提供当班 `shift` 和明确的 `year`、`month`、`day`。系统根据店铺当前该班次的认领人，直接将该值归档为专员绩效和月度回复。店铺数据中心的小时数据不会参与该统计。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "shift": "evening",
    "year": 2026,
    "month": 9,
    "day": 15,
    "specialist_reply_count": 88,
    "specialist_timeout_count": 2,
}
response = requests.post(
    f"{BASE_URL}/api/v1/shift-daily-summaries/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 9. 获取店铺最新早班基线

`GET /api/v1/shift-baselines/morning/?id={店铺ID}`

仅传店铺 ID 即可获取该店铺最近一次上传的早班基线，包含早班专员、日期及全部班次指标。`id` 优先按店铺编号匹配；若传数字且找不到店铺编号，会回退按系统店铺主键查询。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/shift-baselines/morning/",
    params={"id": "pdd_90001"},
    timeout=15,
)
response.raise_for_status()
morning_baseline = response.json()["data"]
print(morning_baseline)
```

## 10. 按系统账号名获取名下店铺

`GET /api/v1/account-stores/?account_name={系统账号名}`

返回该系统账号在无主店铺中心认领的全部店铺，以及其担任的“负责人 1”或“负责人 2”席位。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/account-stores/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
shops = response.json()["data"]
print(shops)
```

`POST /api/v1/accounts/capture-id/`

账号必须先在“账号管理中心”创建。传账号名和账号 ID 即可；若账号名可能在多个店铺相同，建议额外传 `shop_id` 来精确限定。

```python
payload = {
    "account_name": "拼多多客服01",
    "account_id": "account_812345",
    "shop_id": "pdd_90001",  # 可选，但推荐传
}
response = requests.post(
    f"{BASE_URL}/api/v1/accounts/capture-id/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 12. 创建待处理事务

`POST /api/v1/pending-tasks/create/`

按店铺创建一条待处理事务。`time_type` 只能传 `normal`（普通）或 `urgent`（紧急），也支持传中文“普通”或“紧急”。使用系统店铺主键时传 `store_id`；使用店铺编号时传 `shop_id`。若同一编号跨平台重复，请额外传 `platform`。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time_type": "urgent",
    "handling_item": "客户申请退款，请尽快跟进",
}
response = requests.post(
    f"{BASE_URL}/api/v1/pending-tasks/create/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])
```

返回数据包含店铺名、处理事项、`is_urgent`、创建时间，以及实时计算的 `elapsed_time`（已等待时间）。

## 13. 获取负责人未处理事务

`GET /api/v1/pending-tasks/`

此接口需要已登录的平台会话。普通负责人只能拿到自己认领店铺的未处理事务；管理员或具有“查看全部店铺数据”权限的用户默认拿到全部。管理员可追加 `account_name={系统账号名}`，筛选指定负责人的事务。

```python
# 当前登录负责人自己的待办
response = requests.get(f"{BASE_URL}/api/v1/pending-tasks/", timeout=15)

# 管理员查看某位负责人名下的待办
response = requests.get(
    f"{BASE_URL}/api/v1/pending-tasks/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
tasks = response.json()["data"]
```

工作台的“标记已处理”按钮会将对应事务置为已处理，并记录处理人和处理时间；已处理事务不会再出现在该接口或工作台列表中。

## 14. AI 知识库与商品资料接口

后台左侧“AI 知识库”包含客户、店铺、商品、客户素材（材质）四个板块。每个对象可维护 `通用`、`售前`、`售后` 三种特殊提示词、问答对和关键词；每条关键词均包含关键词、匹配规则和对应回答，规则为 `exact`（完全一样）或 `contains`（包含）。所有登录用户可查看知识库，只有对应客户下已认领店铺的负责人或平台管理员可以修改。

店铺知识库会显示继承自客户的特殊提示词、问答对、关键词，可对每一条单独屏蔽或恢复；商品知识库会显示继承自客户、店铺、商品材质的内容，也可逐条屏蔽。屏蔽仅影响下方的汇总接口，原始上游知识不会删除。店铺屏蔽的客户内容不会再继续传入商品；客户材质知识仅由商品的单个材质标注关联。

### 14.1 商品入库

`POST /api/v1/ai/products/upsert/`

兼容哈基米平台的商品数据格式。商品数据可放进 `zl` 对象或其 JSON 字符串中；店铺数据使用外层或 `zl` 中的 `platform` 与 `shopSN/shopid`。店铺必须已存在。以“平台 + 店铺号 + 商品号”覆盖写入，未传 `goods_intro` 时保留已有简介，其他原始商品字段完整保存在返回的 `data` 中。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 是 | `pdd` / `拼多多` / `douyin` / `抖音` |
| `shopSN` 或 `shopid` | 是 | 店铺编号 |
| `goods_id` | 是 | 商品编号 |
| `zl` | 推荐 | 原始商品 JSON；不使用时，可将商品字段直接放在请求体顶层 |

```python
payload = {
    "platform": "pdd",
    "zl": {
        "shopSN": "pdd_90001",
        "goods_id": "932556796841",
        "goods_name": "纯棉短袖",
        "mainimgurls": ["https://img.example.com/product-main.jpg"],
        "detailimgurls": ["https://img.example.com/product-detail.jpg"],
        "values": [{"name": "颜色", "value": "白色"}],
        "skudetails": [{"skuname": "白色/L", "sku_id": "sku-001", "quantity": 5000, "price": 2380}],
    },
}
response = requests.post(f"{BASE_URL}/api/v1/ai/products/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json()["data"])
```

### 14.2 读取已入库商品

`GET /api/v1/ai/products/?platform=pdd&shopid=pdd_90001&goods_id=932556796841`

返回商品标题、属性、SKU、`sku_details`（SKU 名称、SKU 编号、库存、原始分值 `price`、元价 `price_yuan`）、`mainimgurls` 主图链接、`detailimgurls` 详情图链接、当前单个材质标注以及完整原始 `data`。`zl` 的 `mainimgurls`、`detailimgurls`、`values`、`skudetails`、`skutypes` 等商品字段会原样保存；AI 知识库商品详情页会显示 HTTP/HTTPS 图片链接缩略图和 SKU 库存价格表。

`username` 和旧字段 `PT` 不需要传。请在请求顶层或 `zl` 中传平台字段 `platform`（`pdd` / `拼多多` / `douyin` / `抖音`）；SKU 使用实际字段 `skuname`、`sku_id`、`quantity`、`price`，其中 `price` 单位为分，页面自动按元显示。

### 14.3 汇总商品 AI 知识

`GET` 或 `POST /api/v1/ai/knowledge/resolve/`

必传 `platform`、`shopid`、`goods_id`、`scene`。`scene` 只支持 `presale` / `售前` 或 `aftersale` / `售后`。接口不执行 AI、关键词或问答匹配，只将通用内容与所传售前/售后内容整理好后返回，供调用方交给其他 AI 使用。

```python
response = requests.post(
    f"{BASE_URL}/api/v1/ai/knowledge/resolve/",
    json={
        "platform": "pdd",
        "shopid": "pdd_90001",
        "goods_id": "932556796841",
        "scene": "售前",
    },
    timeout=15,
)
response.raise_for_status()
data = response.json()["data"]
```

响应中的 `product` 包含标题、属性、SKU、完整原始商品数据和材质标注；`knowledge.special_prompts`、`knowledge.qas`、`knowledge.keywords` 依次包含客户、店铺、命中材质、商品四层的有效内容。每条内容都带有 `source`（`customer` / `store` / `material` / `product`）和场景。关键词另带有 `match_type` 与中文 `match_type_name`，不会省略“完全一样/包含”规则。

> 以上接口按需求不鉴权，请仅部署在可信内网，并通过防火墙限制来源地址。

## 常见状态码

| 状态码 | 含义 |
| --- | --- |
| `200` | 查询或更新成功 |
| `201` | 已创建新的店铺 Cookie |
| `400` | 参数缺失、字段格式错误或 JSON 不合法 |
| `404` | 店铺或账号不存在 |
| `409` | 店铺编号跨平台重复，需要补传 `platform` |
