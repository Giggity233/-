# 蘑菇头中控平台接口文档

## 基础约定

- 服务地址示例：`http://127.0.0.1:8000`
- 所有采集接口均使用 JSON 请求体（GET 请求除外），不需要 `HEADERS`、Cookie 或 API Key。
- 平台可传英文 `pdd` / `douyin` / `jingdong`，也可传中文 `拼多多` / `抖音` / `京东`。
- 成功响应统一有 `{"ok": true}`；失败响应为 `{"ok": false, "message": "原因"}`。

下面示例共用：

```python
import requests

BASE_URL = "http://127.0.0.1:8000"
```

## 1. 获取所有启用客户

`GET /api/v1/customers/`

返回 `id` 和客户 `name`；禁用客户不返回。

```python
response = requests.get(f"{BASE_URL}/api/v1/customers/", timeout=15)
response.raise_for_status()
customers = response.json()["data"]
print(customers)
```

## 2. 新增或更新店铺 Cookie

`POST /api/v1/cookies/upsert/`

接口会先以 `shop_id` 查找已有店铺。已有且店铺编号唯一时，只传 `shop_id` 与 `cookie` 即可更新 Cookie 和更新时间；若该编号跨平台重复，请额外传 `platform` 进行区分。找不到已有店铺时，会新建店铺并进入无主店铺中心，此时必须提供店铺基本信息。客户**不能也不需要**通过此接口上传，后续由用户在无主店铺认领时手工绑定。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 新增时是；更新跨平台重复编号时是 | `pdd`、`douyin`、`jingdong` 或中文平台名 |
| `shop_id` | 是 | 店铺 ID/编号 |
| `shop_name` | 新增时是 | 店铺名称 |
| `cookie` | 是 | 完整 Cookie 字符串 |
| `main_category` | 否 | 主营类目，缺省为 `notfind` |
| `cookie_status` | 否 | `valid`、`invalid` 或 `disabled`，默认 `valid` |

```python
payload = {
    "platform": "pdd",
    "shop_id": "pdd_90001",
    "shop_name": "蘑菇头旗舰店",
    "cookie": "PDDAccessToken=example; ...",
    "main_category": "家居百货",
}
response = requests.post(f"{BASE_URL}/api/v1/cookies/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json())
```

仅更新已有店铺 Cookie：

```python
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/upsert/",
    json={"shop_id": "pdd_90001", "cookie": "新的完整Cookie"},
    timeout=15,
)
response.raise_for_status()
```

## 3. 按平台获取 Cookie 信息

`GET /api/v1/cookies/?platform={platform}`

返回该平台全部店铺的店铺 ID、店铺名、所属客户、主营类目、Cookie 状态和更新时间，以及该店铺的原始 `cookie`。每个店铺返回的专员账号和机器人账号均包含账号名、账号 ID、账号类型、登录账号及登录密码；没有抓取到 ID 时，字段为 `该id没抓`。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "拼多多"},
    timeout=15,
)
response.raise_for_status()
for shop in response.json()["data"]:
    print(shop["shop_name"], shop["shop_id"], shop["human_accounts"], shop["bot_accounts"])
```

## 4. 按平台和客户获取 Cookie 信息

仍使用 `GET /api/v1/cookies/`，在平台基础上额外提供客户名称或客户 ID。

```python
# 按客户名称
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer": "华东客户"},
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])

# 按客户 ID
response = requests.get(
    f"{BASE_URL}/api/v1/cookies/",
    params={"platform": "douyin", "customer_id": 1},
    timeout=15,
)
```

### 机器人 Cookie 存取接口

机器人 Cookie 与人工 Cookie 独立存储，上传和读取参数、响应字段均与人工 Cookie 接口一致；响应中的 `cookie` 和 `cookie_updated_at` 分别为机器人 Cookie 内容和更新时间。它不会覆盖人工 Cookie，也不会触发专员账号 ID 自动识别。店铺不存在时的创建规则和 `POST /api/v1/cookies/upsert/` 相同。

上传或更新：`POST /api/v1/robot-cookies/upsert/`

```python
payload = {
    "platform": "pdd",
    "shop_id": "pdd_90001",
    "shop_name": "蘑菇头旗舰店",
    "cookie": "机器人完整 Cookie",
}
response = requests.post(f"{BASE_URL}/api/v1/robot-cookies/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json()["data"])
```

读取：`GET /api/v1/robot-cookies/?platform={platform}`。同样可额外传 `customer` 或 `customer_id` 筛选。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/robot-cookies/",
    params={"platform": "pdd"},
    timeout=15,
)
response.raise_for_status()
robot_cookies = response.json()["data"]
```

## 5. 将店铺 Cookie 标记为失效

`POST /api/v1/cookies/invalidate/`

`shop_id` 为必填。若同一店铺编号在两个平台同时存在，请同时传 `platform`，避免误操作。

```python
payload = {"shop_id": "pdd_90001", "platform": "pdd"}
response = requests.post(
    f"{BASE_URL}/api/v1/cookies/invalidate/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 6. 上传专员店铺运营数据

`POST /api/v1/store-metrics/upsert/`

此接口只上传专员及非机器人店铺指标，会覆盖同名最新指标并自动记录更新时间。负责人由系统在首次认领店铺时确定，不接收接口上传。机器人数据必须改用下一节的独立接口。店铺数据仅是客观店铺数据，不区分负责人 1、负责人 2，也不参与专员班次统计。

`shop_id` 和 `time` 必填。`time` 是 `0` 到 `23` 的整数，代表这份数据属于当天的哪个整点小时；即使补传历史小时数据，也必须传对应的 `time`。当店铺编号可能跨平台重复时，`platform` 必填。可选的 `report_date` 使用 `YYYY-MM-DD`，用于补传其他日期；不传默认当天。其余指标均可按实际采集情况选择性传递，未传指标保留上一次数值。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `specialist_reply_count` | 整数 | 专员回复数量 |
| `specialist_three_minute_reply_rate` | 数字 | 专员 3 分钟回复率，如 `98.50` |
| `specialist_timeout_count` | 整数 | 非拼多多店铺的专员超时数量；拼多多会由系统自动计算 |
| `specialist_yesterday_average_response_seconds` | 数字或文字 | 专员昨日平均响应（秒） |
| `pending_after_sales` | 整数 | 待处理售后数量 |
| `pending_tickets` | 整数 | 待处理工单数量 |
| `today_order_count` | 整数 | 今日订单数 |
| `today_turnover` | 数字 | 今日营业金额 |
| `today_ad_spend` | 数字 | 今日广告金额 |
| `store_experience_score` | 数字 | 店铺体验分 |
| `service_experience_score` | 数字或文字 | 服务体验分 |

`咨询数`不再由本接口传入，系统会始终按“专员回复数量 + 机器人完结回复数量”计算。机器人没有数据、传 `null` 或出现文字状态时，机器人完结回复数量按 `0` 参与计算。

数值指标必须大于或等于 0。任一指标也可以传 `null`（Python 调用时为 `None`）或文字，例如 `"无权限"`、`"接口维护中"`；页面会保留相应状态并写入对应历史小时快照。

拼多多的专员超时数量和机器人超时数量均由系统按“总咨询人数 ×（1 − 3 分钟人工回复率）”计算，接口上传的这两个原始值不会采用。

拼多多 `https://mms.pinduoduo.com/chats/getCsRealTimeReplyData` 的响应也可直接作为此接口请求体的一部分：在外层补齐 `shop_id`、`platform` 和 `time` 后，系统会读取 `result.recv_user` 写入专员回复数量，并将 `result.reply_rate` 从小数换算为百分比后写入专员 3 分钟回复率。例如 `reply_rate: 1.0` 会保存为 `100.00%`。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time": 16,
    "report_date": "2026-09-15",
    "specialist_reply_count": 155,
    "specialist_three_minute_reply_rate": 97.80,
    "specialist_yesterday_average_response_seconds": 82.5,
    "pending_after_sales": 9,
    "pending_tickets": 2,
    "today_order_count": 68,
    "today_turnover": 12580.30,
    "today_ad_spend": 860.00,
    "store_experience_score": 4.82,
    "service_experience_score": "无权限",
}
response = requests.post(
    f"{BASE_URL}/api/v1/store-metrics/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 7. 上传机器人店铺数据

`POST /api/v1/robot-metrics/upsert/`

此接口只上传机器人指标。`shop_id`、`time` 必填，`platform`、`report_date` 的规则与专员店铺数据接口相同。每次上传后，系统会用最新的专员回复数量和机器人完结回复数量自动重算咨询数；机器人完结回复数量为 `null`、文字状态或没有上传时，按 `0` 计算。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `robot_completed_reply_count` | 整数或文字 | 机器人完结回复数量 |
| `robot_completed_reply_rate` | 数字或文字 | 机器人完结回复率 |
| `robot_transferred_count` | 整数或文字 | 机器人转出数量 |
| `robot_timeout_count` | 整数或文字 | 非拼多多店铺的机器人超时数量；拼多多会由系统自动计算 |
| `robot_three_minute_reply_rate` | 数字或文字 | 机器人 3 分钟回复率 |

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time": 16,
    "report_date": "2026-09-15",
    "robot_completed_reply_count": 31,
    "robot_completed_reply_rate": 16.67,
    "robot_transferred_count": 12,
    "robot_three_minute_reply_rate": 99.10,
}
response = requests.post(
    f"{BASE_URL}/api/v1/robot-metrics/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 8. 上传专员班次日总结（月度回复来源）

`POST /api/v1/shift-daily-summaries/upsert/`

此接口用于上传早班或晚班各自独立的专员最终基线。传参字段与专员店铺数据接口相同（不接收机器人字段）；另需提供当班 `shift` 和明确的 `year`、`month`、`day`。系统根据店铺当前该班次的认领人，直接将该值归档为专员绩效和月度回复。店铺数据中心的小时数据不会参与该统计。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "shift": "evening",
    "year": 2026,
    "month": 9,
    "day": 15,
    "specialist_reply_count": 88,
    "specialist_timeout_count": 2,
}
response = requests.post(
    f"{BASE_URL}/api/v1/shift-daily-summaries/upsert/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

## 9. 获取店铺最新早班基线

`GET /api/v1/shift-baselines/morning/?id={店铺ID}`

仅传店铺 ID 即可获取该店铺最近一次上传的早班基线，包含早班专员、日期及全部班次指标。`id` 优先按店铺编号匹配；若传数字且找不到店铺编号，会回退按系统店铺主键查询。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/shift-baselines/morning/",
    params={"id": "pdd_90001"},
    timeout=15,
)
response.raise_for_status()
morning_baseline = response.json()["data"]
print(morning_baseline)
```

## 10. 按系统账号名获取名下店铺

`GET /api/v1/account-stores/?account_name={系统账号名}`

返回该系统账号在无主店铺中心认领的全部店铺，以及其担任的“负责人 1”或“负责人 2”席位。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/account-stores/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
shops = response.json()["data"]
print(shops)
```

## 11. 回传或自动抓取账号 ID

`POST /api/v1/accounts/capture-id/`

账号必须先在“账号管理中心”创建。仍可传 `account_name` 和 `account_id` 手动回传；账号 ID 也可以在页面的账号编辑表单中手动修改。

专员登录后，采集端可改为传完整 `cookie`：系统会自动匹配该店铺中尚未填写账号 ID 的专员记录，再按平台解析并保存。拼多多读取 `PASS_ID` 最后一个下划线后的数字；抖音读取 `PIGEON_CID`。已有账号 ID 的记录不会被自动覆盖，仍可在账号编辑页或通过显式 `account_id` 手动修改。若同店有多个未填写 ID 的专员，请传入 `account_name` 或 `login_account` 以精确匹配。

```python
payload = {
    "account_name": "拼多多客服01",
    "account_id": "account_812345",
    "shop_id": "pdd_90001",  # 可选，但推荐传
}
response = requests.post(
    f"{BASE_URL}/api/v1/accounts/capture-id/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json())
```

自动抓取拼多多专员账号 ID：

```python
payload = {
    "account_name": "拼多多客服01",
    "shop_id": "pdd_90001",
    "cookie": "...; PASS_ID=1-example_735291215_156012866; ...",
}
response = requests.post(
    f"{BASE_URL}/api/v1/accounts/capture-id/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["account_id"])  # 156012866
```

也可以在上传/更新 Cookie 时，额外传入 `account_name`（或 `login_account`）；系统会在该 Cookie 保存成功后自动更新对应专员的账号 ID，响应 `data.captured_account_id` 会返回抓取结果。

## 12. 创建待处理事务

`POST /api/v1/pending-tasks/create/`

按店铺创建一条待处理事务。`time_type` 只能传 `normal`（普通）或 `urgent`（紧急），也支持传中文“普通”或“紧急”。使用系统店铺主键时传 `store_id`；使用店铺编号时传 `shop_id`。若同一编号跨平台重复，请额外传 `platform`。

```python
payload = {
    "shop_id": "pdd_90001",
    "platform": "pdd",
    "time_type": "urgent",
    "handling_item": "客户申请退款，请尽快跟进",
}
response = requests.post(
    f"{BASE_URL}/api/v1/pending-tasks/create/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])
```

返回数据包含店铺名、处理事项、`is_urgent`、创建时间，以及实时计算的 `elapsed_time`（已等待时间）。

## 13. 获取负责人未处理事务

`GET /api/v1/pending-tasks/`

此接口需要已登录的平台会话。普通负责人只能拿到自己认领店铺的未处理事务；管理员或具有“查看全部店铺数据”权限的用户默认拿到全部。管理员可追加 `account_name={系统账号名}`，筛选指定负责人的事务。

```python
# 当前登录负责人自己的待办
response = requests.get(f"{BASE_URL}/api/v1/pending-tasks/", timeout=15)

# 管理员查看某位负责人名下的待办
response = requests.get(
    f"{BASE_URL}/api/v1/pending-tasks/",
    params={"account_name": "客服系统账号"},
    timeout=15,
)
response.raise_for_status()
tasks = response.json()["data"]
```

工作台的“标记已处理”按钮会将对应事务置为已处理，并记录处理人和处理时间；已处理事务不会再出现在该接口或工作台列表中。

## 14. 新增账号密码登记记录

`POST /api/v1/account-password-registrations/create/`

创建一条独立的账号密码登记记录。所有登录账号可共同查看、修改、删除登记数据；该表不关联店铺、客户或账号管理中心中的任何数据。所有业务字段均可不传。平台字段默认“拼多多”，页面可手工输入新平台，也可从所有历史登记记录的共享下拉建议中点选。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `shop_name` / `store_name` | 否 | 店铺名 |
| `platform` | 否 | 平台，默认 `拼多多` |
| `account_name` | 否 | 账号名 |
| `account_type` | 否 | `specialist`（专员账号，默认）或 `robot`（机器人账号） |
| `login_account` / `login_password` | 否 | 登录账号、登录密码 |
| `phone` | 否 | 手机号 |
| `responsible_1` / `responsible_2` | 否 | 负责人 1、负责人 2 |
| `customer` | 否 | 客户 |
| `remarks` | 否 | 备注 |
| `operator_name` | 否 | 接口调用方可选传的操作人；页面新增/修改时自动写入当前登录人的负责人姓名 |

字段也兼容对应中文键名。为兼容旧调用，`specialist_account` / `specialist`、`robot_account` / `robot` 仍可传入：系统会将值写入账号名，并自动判断账号类型。

```python
payload = {
    "shop_name": "蘑菇头旗舰店",
    "platform": "拼多多",
    "account_name": "客服主账号",
    "account_type": "specialist",
    "login_account": "service-main",
    "login_password": "example-password",
    "responsible_1": "张三",
    "customer": "华东客户",
    "remarks": "仅用于账号登记",
}
response = requests.post(
    f"{BASE_URL}/api/v1/account-password-registrations/create/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"])
```

### 14.1 查询账号密码登记列表（登录态）

`GET /api/v1/account-password-registrations/`

供账号密码登记页面异步加载表格数据；需要已登录会话。支持 `responsible`、`customer`、`store`（店铺名）的模糊筛选和 `page` 分页参数，按添加时间倒序返回。响应的 `data.rows` 包含登记字段、`created_at_display`、`edit_url`、`delete_url`，`data.pagination` 包含总数及分页信息；前端可直接据此渲染列表与操作按钮。

```text
GET /api/v1/account-password-registrations/?responsible=张三&customer=华东客户&store=旗舰店&page=1
```

### 14.2 新增图片对应文字

`POST /api/v1/image-text-registrations/create/`

外部服务可传入 HTTP/HTTPS 图片链接及对应文字。该接口无需登录；登录用户可在“登记表格 → 图片对应文字”独立页面异步查看图片与文字、修改文字或删除记录。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `image_url` | 是 | 图片链接；兼容 `imageUrl`、`image`、`url` |
| `text` 或 `content` | 是 | 图片右侧显示的对应文字；兼容 `article` |

```python
response = requests.post(
```

## 15. AI 知识库与商品资料接口

后台左侧“AI 知识库”包含客户、店铺、商品、客户素材（材质）四个板块。每个对象可维护 `通用`、`售前`、`售后` 三种特殊提示词、问答对和关键词；每条关键词均包含关键词、匹配规则和对应回答，规则为 `exact`（完全一样）或 `contains`（包含）。所有登录用户可查看知识库，只有对应客户下已认领店铺的负责人或平台管理员可以修改。

店铺知识库会显示继承自客户的特殊提示词、问答对、关键词，可对每一条单独屏蔽或恢复；商品知识库会显示继承自客户、店铺、客户素材的内容，也可逐条屏蔽。屏蔽仅影响下方的汇总接口，原始上游知识不会删除。店铺屏蔽的客户内容不会再继续传入商品。

商品可通过两种方式继承客户素材知识：手动标注一个客户素材时，继承该素材的提示词、问答对和关键词；或者商品标题、SKU、任一属性中**区分大小写**地包含客户素材名称时，自动继承该素材的提示词、问答对和关键词。自动匹配不写入商品资料，商品名称/SKU/属性更新后会即时按最新内容生效或取消；除逐条屏蔽外，也可以在客户素材详情对某一商品屏蔽该素材的全部内容。

### 15.1 商品入库

`POST /api/v1/ai/products/upsert/`

兼容哈基米平台的商品数据格式。商品数据可放进 `zl` 对象或其 JSON 字符串中；店铺数据使用外层或 `zl` 中的 `platform` 与 `shopSN/shopid`。店铺必须已存在。以“平台 + 店铺号 + 商品号”覆盖写入，未传 `goods_intro` 时保留已有简介，其他原始商品字段完整保存在返回的 `data` 中。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 是 | `pdd` / `拼多多` / `douyin` / `抖音` / `jingdong` / `京东` |
| `shopSN` 或 `shopid` | 是 | 店铺编号 |
| `goods_id` | 是 | 商品编号 |
| `zl` | 推荐 | 原始商品 JSON；不使用时，可将商品字段直接放在请求体顶层 |

```python
payload = {
    "platform": "pdd",
    "zl": {
        "shopSN": "pdd_90001",
        "goods_id": "932556796841",
        "goods_name": "纯棉短袖",
        "mainimgurls": ["https://img.example.com/product-main.jpg"],
        "detailimgurls": ["https://img.example.com/product-detail.jpg"],
        "values": [{"name": "颜色", "value": "白色"}],
        "skudetails": [{"skuname": "白色/L", "sku_id": "sku-001", "quantity": 5000, "price": 2380}],
    },
}
response = requests.post(f"{BASE_URL}/api/v1/ai/products/upsert/", json=payload, timeout=15)
response.raise_for_status()
print(response.json()["data"])
```

#### 15.1.1 客户素材继承与整项屏蔽

客户素材知识库列表支持按客户筛选、分页和删除。进入某个素材后，会列出所有通过手动标注，或商品标题、SKU、属性区分大小写自动命中该素材名称的商品。

在该列表中可对单个商品执行“屏蔽整个素材”或“恢复继承”。整项屏蔽仅作用于该商品和该客户素材，会使素材的特殊提示词、问答对、关键词（包括之后新增的内容）都不再出现在商品知识汇总和关键词匹配结果中；不会影响该商品的其他素材、客户、店铺或商品自身知识。手动素材标注仍会保留，方便后续恢复继承。

删除客户素材会删除该素材下的知识内容和整项屏蔽记录，并自动取消所有商品对该素材的手动标注。

### 15.2 读取已入库商品

`GET /api/v1/ai/products/?platform=pdd&shopid=pdd_90001&goods_id=932556796841`

返回商品标题、属性、SKU、`sku_details`（SKU 名称、SKU 编号、库存、原始分值 `price`、元价 `price_yuan`）、`mainimgurls` 主图链接、`detailimgurls` 详情图链接、当前单个材质标注以及完整原始 `data`。`zl` 的 `mainimgurls`、`detailimgurls`、`values`、`skudetails`、`skutypes` 等商品字段会原样保存；AI 知识库商品详情页会显示 HTTP/HTTPS 图片链接缩略图和 SKU 库存价格表。

`username` 和旧字段 `PT` 不需要传。请在请求顶层或 `zl` 中传平台字段 `platform`（`pdd` / `拼多多` / `douyin` / `抖音` / `jingdong` / `京东`）；SKU 使用实际字段 `skuname`、`sku_id`、`quantity`、`price`，其中 `price` 单位为分，页面自动按元显示。

### 15.3 汇总商品 AI 知识

`GET` 或 `POST /api/v1/ai/knowledge/resolve/`

必传 `platform`、`shopid`、`goods_id`、`scene`。`scene` 只支持 `presale` / `售前` 或 `aftersale` / `售后`。接口不执行 AI、关键词或问答匹配，只将通用内容与所传售前/售后内容整理好后返回，供调用方交给其他 AI 使用。

```python
response = requests.post(
    f"{BASE_URL}/api/v1/ai/knowledge/resolve/",
    json={
        "platform": "pdd",
        "shopid": "pdd_90001",
        "goods_id": "932556796841",
        "scene": "售前",
    },
    timeout=15,
)
response.raise_for_status()
data = response.json()["data"]
```

响应中的 `product` 包含标题、属性、SKU、完整原始商品数据和材质标注；`knowledge.special_prompts`、`knowledge.qas`、`knowledge.keywords` 都会包含客户、店铺、手动或自动命中的客户素材、商品四层的有效内容。每条内容都带有 `source`（`customer` / `store` / `material` / `product`）、`source_name` 和场景。关键词另带有 `match_type` 与中文 `match_type_name`，不会省略“完全一样/包含”规则。

### 15.4 批量新增商品问答对

`POST /api/v1/ai/knowledge/products/qas/add/`

按店铺号和商品号向**商品知识库**新增问答对。`qas` 可一次传入多组问答，且必须通过 `scene` 指定写入“通用”“售前”或“售后”。写入“通用”的内容会在调用 15.3 汇总接口时同时用于售前和售后；写入“售前”或“售后”的内容只会出现在对应场景。`shopid` 也可写为 `shop_id` 或 `shopSN`。当同一店铺号、商品号跨平台重复时，额外传 `platform` 进行区分。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `shopid` | 是 | 店铺号，也兼容 `shop_id`、`shopSN` |
| `goods_id` | 是 | 商品号 |
| `scene` | 是 | `general` / `通用`、`presale` / `售前`、`aftersale` / `售后` |
| `qas` | 是 | 问答数组，每项均包含 `question` 和 `answer` |
| `platform` | 否 | `pdd` / `拼多多` / `douyin` / `抖音` / `jingdong` / `京东`；店铺号跨平台重复时必填 |

```python
payload = {
    "shopid": "pdd_90001",
    "goods_id": "932556796841",
    "scene": "presale",
    "qas": [
        {"question": "这件衣服是什么材质？", "answer": "商品详情页已标明材质和成分，请以页面信息为准。"},
        {"question": "什么时候发货？", "answer": "通常会在付款后尽快安排发货，具体以订单物流状态为准。"},
    ],
}
response = requests.post(
    f"{BASE_URL}/api/v1/ai/knowledge/products/qas/add/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["created_count"])  # 2
```

### 15.5 追加商品提示词

`POST /api/v1/ai/knowledge/products/prompts/append/`

按店铺号和商品号向**商品知识库**指定场景的特殊提示词末尾追加一句提示词，不会覆盖该场景的原有内容；原内容与新内容之间会自动换行。`scene` 必填：通用提示词会同时用于售前和售后，售前、售后提示词仅用于各自场景。指定场景原本没有提示词时，接口会自动创建一条。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `shopid` | 是 | 店铺号，也兼容 `shop_id`、`shopSN` |
| `goods_id` | 是 | 商品号 |
| `scene` | 是 | `general` / `通用`、`presale` / `售前`、`aftersale` / `售后` |
| `prompt` | 是 | 需要追加的一句提示词，也兼容字段名 `content` |
| `platform` | 否 | 店铺号跨平台重复时必填 |

```python
payload = {
    "shopid": "pdd_90001",
    "goods_id": "932556796841",
    "scene": "aftersale",
    "prompt": "回答商品问题时不要承诺具体到货日期，应以物流页面为准。",
}
response = requests.post(
    f"{BASE_URL}/api/v1/ai/knowledge/products/prompts/append/",
    json=payload,
    timeout=15,
)
response.raise_for_status()
print(response.json()["data"]["content"])
```

### 15.6 按商品匹配关键词

`GET` 或 `POST /api/v1/ai/knowledge/keywords/match/`

传入一句待匹配文字和商品 ID，接口会读取该商品当前有效的客户、店铺、客户素材和商品关键词（包含自动命中客户素材继承的关键词），并执行关键词的 `exact`（完全一样）或 `contains`（包含）规则。商品或上游已屏蔽的关键词不会参与匹配。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 待匹配的一句话；兼容 `content`、`message` |
| `product_id` | 是* | 商品业务 ID，即 `goods_id`；也可显式传 `goods_id` |
| `product_pk` | 是* | 商品系统主键；与 `product_id` 二选一 |
| `shopid` | 否 | 同一商品业务 ID 存在多条记录时必填；兼容 `shop_id`、`shopSN` |
| `platform` | 否 | 店铺号跨平台重复时必填 |
| `scene` | 否 | 指定 `general` / `通用`、`presale` / `售前` 或 `aftersale` / `售后`；不传则匹配全部场景 |

```python
response = requests.post(
    f"{BASE_URL}/api/v1/ai/knowledge/keywords/match/",
    json={
        "product_id": "932556796841",
        "shopid": "pdd_90001",
        "text": "请问这件商品支持七天无理由退货吗？",
    },
    timeout=15,
)
response.raise_for_status()
result = response.json()
print(result["answer"])  # 命中时返回回答；不命中时为“无匹配”
```

响应的 `matched` 表示是否命中；`answer` 为所有命中回答（多条时以换行连接），`data.matches` 会保留每条命中的关键词、来源和匹配规则。

### 15.7 查询商品催单话术

`GET` 或 `POST /api/v1/ai/order-urging-scripts/`

催单话术独立于 AI 提示词、问答对和关键词。后台可在客户、店铺、商品知识库详情中分别配置“待支付”和“未下单”两类话术：店铺默认继承客户，商品默认继承店铺；两类话术分别继承，也可在下级单独屏蔽上级。调用时只需传商品系统主键 `product_id`，接口返回该商品最终生效的话术；没有可用话术的字段固定返回字符串 `无`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `product_id` | 是 | 商品系统主键，即商品知识库页面所用的内部 ID，不是业务商品号 `goods_id` |

```python
response = requests.get(
    f"{BASE_URL}/api/v1/ai/order-urging-scripts/",
    params={"product_id": 123},
    timeout=15,
)
response.raise_for_status()
scripts = response.json()["data"]
# {"product_id": 123, "pending_payment": "待支付话术", "unplaced_order": "未下单话术"}
```

`POST` 时发送 JSON，例如 `{"product_id": 123}`。商品不存在时返回 `404`；缺少或非法的 `product_id` 返回 `400`。这是新增接口，不会修改现有任何接口的地址、参数或响应结构。

### 15.8 查询店铺催单话术

`GET` 或 `POST /api/v1/ai/order-urging-scripts/store/`

传入店铺编号即可读取店铺知识库中最终生效的“待支付”和“未下单”催付话术；店铺未单独配置时会自动返回其客户继承的话术，已屏蔽上级或没有可用话术时固定返回字符串 `无`。店铺编号在多个平台重复时，再补传 `platform`（`pdd` / `拼多多` / `douyin` / `抖音` / `jingdong` / `京东`）即可区分。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `store_id` | 是 | 店铺编号；兼容 `shop_id`、`shopid` |
| `platform` | 否 | 店铺编号跨平台重复时必填 |
| `store_pk` | 否 | 系统店铺主键；传入后优先按此字段定位店铺 |

```python
response = requests.get(
    f"{BASE_URL}/api/v1/ai/order-urging-scripts/store/",
    params={"store_id": "pdd_90001"},
    timeout=15,
)
response.raise_for_status()
scripts = response.json()["data"]
# {"store_id": "pdd_90001", "store_pk": 12, "platform": "pdd", "pending_payment": "待支付话术", "unplaced_order": "未下单话术"}
```

`POST` 时发送 JSON，例如 `{"store_id": "pdd_90001"}`。店铺不存在时返回 `404`；缺少店铺编号、编号跨平台重复但未传平台时返回 `400`。

## 16. 获取店铺售后策略

`GET /api/v1/after-sales-strategies/?shopid={店铺编号}`

按已配置策略的店铺编号获取售后策略 JSON。只传 `shopid` 即可；当同一店铺编号在多个平台都配置了策略时，必须额外传 `platform`（`pdd` / `拼多多` / `douyin` / `抖音` / `jingdong` / `京东`）进行区分。未配置策略时返回 `404`。

响应会返回店铺、客户、协商方式中的补偿/补发/退款执行次数、补偿类型（`ratio` 补偿比例或 `amount` 补偿金额）、补偿上下限、质保天数，以及按补偿阶数输出的补偿配置。协商方式中某项为 `0` 表示不执行。

```python
response = requests.get(
    f"{BASE_URL}/api/v1/after-sales-strategies/",
    params={"shopid": "pdd_90001"},
    timeout=15,
)
response.raise_for_status()
strategy = response.json()["data"]
print(strategy["negotiation_methods"])
# {"compensation": 2, "replacement": 1, "refund": 0}
```

> 以上接口按需求不鉴权，请仅部署在可信内网，并通过防火墙限制来源地址。

## 常见状态码

| 状态码 | 含义 |
| --- | --- |
| `200` | 查询或更新成功 |
| `201` | 已创建新的店铺 Cookie |
| `400` | 参数缺失、字段格式错误或 JSON 不合法 |
| `404` | 店铺或账号不存在 |
| `409` | 店铺编号跨平台重复，需要补传 `platform` |

## 发票接口

店铺编号统一使用 `store_id`（即店铺外部编号）；如需使用系统内部主键，请传 `store_pk`。店铺编号跨平台重复时必须附带 `platform`（`pdd`、`douyin` 或 `jingdong`）。发票写入接口不接收 PDF，PDF 由发票中心页面补传。

### 写入发票原始信息

`POST /api/v1/invoices/upload/`

可直接提交一条对象，或提交 `{"invoices": [...]}` 批量写入。新记录始终为 `pending`（未处理）。

```json
{
  "store_id": "pdd_90001",
  "platform": "pdd",
  "order_no": "202610160001",
  "title_type": "企业",
  "company_subject": "示例公司",
  "invoice_title": "示例公司",
  "taxpayer_id": "913xxxxxxxx",
  "product_name": "商品名称",
  "quantity": 2,
  "amount": 19.9
}
```

### 拉取当天待处理发票

`GET /api/v1/invoices/pending/?date=YYYY-MM-DD`

每次最多返回 100 条状态为 `pending` 的记录，返回店铺名称、店铺 ID、订单号和 `pdf_download_url`。无 PDF 时下载链接为空字符串。

### 批量回传发票结果

`POST /api/v1/invoices/status/`

`status` 只支持 `success`（成功）与 `failed`（失败）；成功或失败后均不会再次被待处理接口返回。失败记录可在发票中心点击“再次上传”恢复为未处理。

### 回传已发送状态并清空

`POST /api/v1/wechat-groups/pending/sent/`

无需请求体。接口返回 `status: "sent"` 后，会立即清空该微信群此前的全部待发送信息，并返回本次清空的 `cleared_count`。

## 已登录 JSON 列表接口

- `GET /api/v1/invoice-center/`：发票中心筛选与翻页，单页最多 50 条。
- `GET /api/v1/message-center/`：留言管理筛选与翻页，单页最多 50 条。

两者均返回 `{"ok": true, "data": {"rows": [...], "pagination": {...}}}`，供页面异步刷新使用。
